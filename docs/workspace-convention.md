# _workspace 산출물 컨벤션

## 1. 기본 규칙

| 항목 | 규칙 |
|------|------|
| 저장 위치 | 프로젝트 루트의 `_workspace/` 아래, **작업별 폴더** 하나씩 |
| 대상 | 작업 계획서, 수행 결과서, 그리고 그 작업의 부속 아티팩트(SQL·로그·스크립트 등) |
| 단위 원칙 | **작업 하나 = 폴더 하나.** 한 작업에 관한 모든 파일은 그 폴더 안에 모은다 |
| 커밋 여부 | 커밋하지 않는다 — 세션/작업 단위의 임시 산출물 |
| 소스코드 관계 | `_workspace/` 문서는 참고용이며, 실제 규칙·컨벤션은 각 모듈의 `CLAUDE.md`가 우선한다 |

---

## 2. 폴더·파일명 규칙

### 2.1 작업 폴더명

패턴: `<날짜>-<작업명>/`

| 항목 | 규칙 | 예시 |
|------|------|------|
| 날짜 | 작업 착수일 `YYYY-MM-DD`를 앞에 붙인다 | `2026-08-25-` |
| 작업명 | 한글로 쓰고, 여러 단어는 하이픈(-)으로 구분한다 | `리프레시-토큰-발급` |
| 금지 | 띄어쓰기·특수문자는 쓰지 않는다 | — |

예시: `_workspace/2026-08-25-리프레시-토큰-발급/`

> 날짜를 앞에 두면 최근 작업 순으로 정렬되고, 같은 작업명이 겹쳐도 충돌하지 않는다.

### 2.2 폴더 안 파일

| 파일 | 이름 | 비고 |
|------|------|------|
| 작업 계획서 | `plan.md` | 착수 전 작성 (3절 구조) |
| 수행 결과서 | `result.md` | 완료 후 작성 (4절 구조) |
| 부속 아티팩트 | 자유 | SQL·로그·스크립트 등 그 작업에서 나온 파일 |

예시 구조:

```
_workspace/
  2026-08-25-리프레시-토큰-발급/
    plan.md
    result.md
  2026-08-07-booking-스키마-초기화/
    plan.md
    result.md
    V1__init_schema.sql
```

## 3. 작업 계획서 구조

```markdown
# Plan: <작업명>

## 목표
- 무엇을, 왜 하는지 1~3줄

## 범위
- 대상 모듈/파일
- 범위 밖(하지 않을 것)

## 단계
1. ...
2. ...

## 완료 기준
- 어떤 상태가 되면 완료로 볼 것인지
```

## 4. 수행 결과서 구조

```markdown
# Result: <작업명>

## 요약
- 계획 대비 실제로 한 일 1~3줄

## 계획 대비 변경 사항
- 계획서와 달라진 부분과 이유 (없으면 "없음")

## 변경 파일
- path/to/file — 변경 내용 한 줄

## 검증
- 실행한 테스트/빌드/확인 방법과 결과

## 후속 작업
- 남은 이슈, 후속 필요 작업 (없으면 "없음")
```

---

## 5. 생명주기

- 작업을 시작하면 `_workspace/<날짜>-<작업명>/` 폴더를 만들고 `plan.md`부터 작성한다.
- 계획서는 착수 전에 작성하고, 진행 중 범위가 바뀌면 갱신한다.
- 결과서는 작업 완료 후 계획서를 참조해 작성한다 — 계획서 없이 결과서만 남기지 않는다.
- 부속 아티팩트(SQL·로그 등)는 같은 작업 폴더 안에 둔다.
- 작업이 끝나고 더 이상 참조할 필요가 없어지면 **폴더째 삭제**한다 (커밋 대상이 아니므로).
