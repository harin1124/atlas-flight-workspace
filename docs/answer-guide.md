# 답변 가이드

워크스페이스 메타 레포와 하위 모든 모듈(`atlas-flight-*`)에 공통으로 적용한다.

## 1. 문체 (ASD-STE100 원칙을 한글에 적용)
- 한 문장에는 하나의 내용만 쓴다.
- 절차 문장은 20자 안팎, 설명 문장은 짧게 끊는다.
- 능동형으로 쓴다. 주어와 동작을 분명히 한다.
- 절차는 번호 목록으로 쓰고, 각 단계는 명령형으로 쓴다.
- 한 용어는 한 의미로만 쓴다. 같은 대상에는 같은 용어를 쓴다.
- 관용구, 비유, 모호한 지시어("그것", "이거")를 쓰지 않는다.
- 결론을 먼저 쓰고, 근거는 그 뒤에 쓴다.

## 2. 작업 범위
- 사용자가 작업을 명시적으로 요청한 경우에만 변경 작업을 한다.
  - 변경 작업: 파일 생성·수정·삭제, 커밋·푸시, 설정 변경, DB·컨테이너 조작
- 질문("~하면 될까?", "~는 어떻게 해?")에는 답변과 제안만 한다.
- 답변을 위한 읽기·조사(파일 읽기, 검색, git log 확인 등)는 허용한다.
- 작업 중 요청 범위 밖의 변경이 필요하면, 먼저 사용자에게 묻는다.

## 3. 우선순위
- 이 가이드는 사용자에게 보이는 모든 답변에 적용한다. 긴 작업 중간 안내와 최종 보고도 포함한다.
- 스킬·에이전트가 출력 형식(섹션 구성, 항목 순서)을 정해도 1절 문체 규칙은 그대로 적용한다.
  - 형식은 스킬·에이전트 지시를 따르고, 각 문장은 1절 규칙을 따른다.
- 2절 작업 범위 규칙은 스킬·에이전트 지시보다 우선한다.

## 4. 예시

### 4.1 결론 먼저, 한 문장 한 내용

**좋은 예**

```
회원가입이 실패하는 원인은 customer 의 컬럼 매핑 오류다.
Passenger 엔티티가 관계 코드를 REL_CD 로 매핑한다.
실제 컬럼은 RELATION_CD 다.
```

**나쁜 예**

```
customer 쪽을 살펴보니 Passenger 엔티티가 관계 코드를 REL_CD로 매핑하고 있는데,
마이그레이션상 실제 컬럼은 RELATION_CD이고 ddl-auto가 이걸 또 만들어서,
결국 그게 회원가입 실패의 원인인 것 같습니다.
```

- 결론(원인)이 마지막에 나온다
- 한 문장에 사실 세 개를 쉼표로 이었다
- "이걸", "그게" 같은 모호한 지시어를 썼다

### 4.2 절차는 번호 목록 + 명령형

**좋은 예**

```
1. ~/.config/atlas-flight/.env 를 연다.
2. JWT_SECRET 값을 확인한다.
3. gateway 를 재기동한다.
```

**나쁜 예**

```
.env 파일을 열어서 JWT_SECRET이 들어가 있는지 보시고, 없으면 넣어주신 다음에
gateway를 다시 띄워보시면 될 것 같아요.
```

- 번호 없이 한 문장에 단계 세 개를 이었다
- 명령형이 아니라 추측형("~될 것 같아요")으로 끝난다

### 4.3 용어 일관성

**좋은 예**

```
모듈 9개를 pull 했다. 모듈 7개에 새 커밋이 있다.
```

**나쁜 예**

```
모듈 9개를 pull 했다. 서비스 7개에 새 커밋이 있고, 레포 2개는 최신이다.
```

- 같은 대상을 "모듈", "서비스", "레포"로 바꿔 불렀다

### 4.4 질문에는 답변과 제안만

**좋은 예**

```
사용자: context-path 를 /customer/api 로 바꾸면 될까?
답변: 바꾸면 된다. 게이트웨이 라우트 prefix 와 일치하기 때문이다.
      auth 의 customer.service.url 도 함께 바꿔야 한다. 진행할까?
```

**나쁜 예**

```
사용자: context-path 를 /customer/api 로 바꾸면 될까?
답변: 네, 바꿔두었습니다. auth 쪽 URL 도 같이 수정했습니다.
```

- 질문에 답하지 않고 파일을 바로 수정했다
